# 回溯之镜（QuickRestart）
<img width="477" height="544" alt="ac0248038a3face82aafdeb304de5aa9" src="https://github.com/user-attachments/assets/f9a2d12b-27b8-41ca-ab17-67791c3db941" />


《杀戮尖塔 2》练习与救场模组 —— 把「重来」做到极致：从重开一个房间到重开整局，全部基于**完整运行快照回滚**，牌序与随机数精确重现。

> 适用于游戏 v0.111+，依赖 [STS2-RitsuLib](https://github.com/BAKAOLC/STS2-RitsuLib)（≥ 0.5.18，兼容 0.6.x）。

## 功能

### 四类重启（暂停菜单，实时显示当前幕数）

| 按钮 | 效果 |
|---|---|
| **重启房间** | 回滚到**进房前**并自动重新进入 —— RNG 一并回滚，手牌/抽牌堆/怪物与首次进房**完全一致**（练习同一场战斗的不同打法）；**商店库存 / 事件 / 宝箱内容同样不会刷新**，反复重启都是同一批 |
| **重启本层（第 N 幕）** | 回滚到**本幕起点** —— 本幕获得的金币 / 卡牌 / 遗物 / 药水 / 血量全部回退；进入每一幕时自动保存幕初快照，**读档继续游戏后依然能回到真正的幕初** |
| **重启本局** | 同一种子从头重开 —— 无痕保护（见下）|
| **重启新局** | 同角色、新随机种子全新开局 |

### 刀下留人

生命归零时弹出「刀下留人」弹窗，战斗冻结：

- **回到地图重新挑战** —— 回滚到**进入本房间之前（选路前）**并停在地图界面：血量 / 牌组 / 金币全部回退，可重新选路，也可重新进入刚才那个节点再战
- **放弃本局** —— 同一种子从头重开

> 「回到地图重新挑战」= 这一格当作还没走过：连地图上的访问记录一并回退，所以能重新进入同一个节点。

### 战后重新挑战

战斗结算的选牌界面提供「重新挑战」按钮：不满意战利品时放弃奖励、整场重打。

### 快捷键（游戏内可自定义）

暂停菜单 → **快捷键设置** → 点击一行后按下新按键（Esc 取消），**即时生效**并写入配置。

默认键位：

| 操作 | 默认键 |
|---|---|
| 重启房间 | `R` |
| 重启本层 | `F` |
| 重启本局 | `T` |
| 重启新局 | `N` |

> 快捷键在战斗中直接可用（无需打开菜单）。**重启房间免确认**，可连按（适合反复练习同一场战斗）；重启本层 / 本局 / 新局仍会弹确认框防误触。

## 无痕保护

所有重启操作（房间 / 本层 / 本局 / 新局）与刀下留人，**都不会污染你的战绩**：

- **不增加失败** —— 被重启的旧局面不会写入挑战历史，不会被记为一次失败
- **不断连胜** —— 连胜（win streak）不会因重启而中断
- **不记录成就 / 不上传统计** —— 旧局面静默消失，仿佛从未发生

> 实现方式：重启期间临时关闭游戏的存档写入开关（`RunManager.ShouldSave`），新局自动恢复 —— 与游戏正常情况下"放弃本局并结算"的流程完全隔离。

## 安装

1. 安装 [STS2-RitsuLib](https://github.com/BAKAOLC/STS2-RitsuLib)（前置库 mod）
2. 将 `QuickRestart` 文件夹（含 `QuickRestart.dll` 与 `QuickRestart.json`）放入游戏目录的 `mods/` 下
3. 启动游戏即可

## 配置

首次运行自动生成：

```
%APPDATA%\SlayTheSpire2\mod_data\QuickRestart\settings.json
```

| 字段 | 说明 |
|---|---|
| `RestartRoomKey` 等四项 | 快捷键（字母/数字/功能键，如 `R`、`Space`、`F1`）|
| `EnableDeathIntercept` | 刀下留人开关 |
| `EnablePostCombatRetry` | 战后重新挑战按钮开关 |
| `ShowConfirmationDialog` | 确认弹窗开关（重启本层/本局/新局与重新挑战；**重启房间不受此开关影响，始终直接执行**）|
| `FastRestartSkipMenu` | 重启跳过主菜单中转（默认开启，显著缩短黑屏；异常时可关闭回退旧流程）|

## 工作原理（简述）

- **重启 = 快照回滚**：进房前 / 幕起点 / 开局自动保存完整运行快照（含 RNG 状态），重启经游戏官方读档流程（`RunState.FromSerializable → SetUpSavedSingleplayer → LoadRun`）精确回滚 —— 与"继续游戏"同一条路径，不做手工状态修补
- **幕初快照持久化**：每次真实进入新幕时，幕初快照同时写入磁盘（`%APPDATA%\SlayTheSpire2\mod_data\QuickRestart\act_start_snapshot.json`，仅保留最新一份，约 50KB）—— 因此"读档继续游戏"后按 `F` 也能回滚到**真正的幕初**，而不是读档那一刻
- **刀下留人 = 双重拦截**：同时拦截 `HandlePlayerDeath` 与失败标记 `LoseCombat`，拦截后立即复活玩家并冻结战斗，等待玩家选择
- **无痕**：重启过程中旧局面不写入 run 历史、不中断连胜、不记失败（详见上文"无痕保护"）

## 更新记录

### v0.1.5 · 2026-09-15

**调整：联机模式下完全不生效**

- **背景**：联机对局由输入同步与校验和保护，单方面本地回滚会被判定为状态不一致 —— 因此本模组不适合在联机中使用。
- **现在**：联机对局中本模组**完全静默**：
  - 快捷键不执行（屏幕提示"联机模式下不可用"）
  - 暂停菜单与战斗结算界面**不显示**本模组按钮
  - 生命归零**不拦截**（交给游戏官方流程）
- **修复**：刀下留人的死亡判断由"玩家列表第一位"改为**本地玩家**（此前在联机对局中，队友死亡会误触发"刀下留人"弹窗）。
- 单人模式完全不受影响。

**修复：控制台打开时快捷键误触发**

- 打开控制台（dev console）时按重启快捷键会误触发本模组功能；现在控制台打开期间快捷键不响应（与游戏自身的输入处理保持一致），不会干扰你在控制台里的输入。

### v0.1.4 · 2026-09-15

**新功能：读档继续游戏也能真正回到「本幕起点」**

- **背景**：游戏存档只保存"当前状态"，不含本幕开场数据 —— 此前用「继续游戏」读档后按 `F`，「重启本层」只能回到**读档那一刻**，玩家感受是"按了没动"。
- **现在**：每次真实进入新幕时，幕初完整快照会自动写入磁盘（`%APPDATA%\SlayTheSpire2\mod_data\QuickRestart\act_start_snapshot.json`，约 50KB，仅保留最新一份）。
  之后无论读档继续、还是大退重开游戏，按 `F` 都能**完整回滚到该幕起点**：金币 / 卡牌 / 遗物 / 药水 / 血量与地图进度全部回退。
- **如实提示**：若本幕开始时 mod 尚未运行（例如首次安装时已处于幕中），磁盘上没有该幕数据，此时重启本层仍退回读档点，过场黑幕会明确写出：`本幕快照来自读档点：只能回到「读档时」的状态`。
- **范围**：作用于「重启本层」（`F`）与暂停菜单「重启本层」；「重启本局」（`T`）语义不变（同种子整局从头）。

**修复：一处运行时异常导致四类重启集体退化**

- **现象**：重启房间变成"牌序重随机的重开"、重启本层变成"仅重进本幕"、刀下留人有时不回到地图而是原地重开战斗。
- **原因**：用于识别"是否同一局"的局标识（游戏内部的时间戳字段）读取方式在运行时不兼容（该字段非公开成员，编译器放行但运行环境拒绝），导致所有快照归属校验失败、全部走兜底路径。
- **修复**：改用标准反射读取；并新增**降级链**（局标识不可用 → 种子比对 → 放行并记日志）—— 单一环节异常不再让功能整体失效。

**改进与加固**

- **重启本层落点兜底**：回滚后若不是地图屏会自动纠正，并在日志记录落点（此前"按了没回地图"无法定位）。
- **过场黑幕提示**：快照来源与回滚目标在黑幕上明确显示（如读档点场景），无需翻日志。
- **性能**：同一局同一幕只尝试一次磁盘读取（避免反复解析快照文件）。

### v0.1.3 · 2026-09-15

**重启房间免确认**

- 按 `R` 或点击暂停菜单「重启房间」→ **直接重启**，不再弹防误触确认框 —— 反复练习同一场战斗时不必每次点确认，可连按。
- 防误触由 **0.5 秒触发冷却**承担（连按不会叠发）；**重启本层 / 本局 / 新局仍保留确认框**（大幅回退操作，误触代价高）。
- 战后「重新挑战」按钮保持原样（仍弹确认框）。
- 配置项 `ShowConfirmationDialog` 语义不变：仍控制其余操作的确认框。

**修复：刀下留人后地图「前进一层」**

- **现象**：触发刀下留人并选择「回到地图重新挑战」后，地图进度 / 位置会凭空前进一格（重启房间也有同类隐患）。
- **原因**：回滚走的是官方「重进最后访问节点」读档路径（`LoadIntoLatestMapCoord`），它会按节点类型**重掷/新建房间**并往地图点历史 **追加快照外的格子**，于是地图被推进一格。
- **修复**：改为**精确落点** ——「回到地图」直接停在地图屏；「重启房间」按原坐标**重新进入本节点**（等价于第一次点击该节点，牌序与商店库存仍与首次一致）；「重启本层」落回本幕起点地图屏。三者都不再改动地图历史。

**修复：问号房（?）重启后内容变化**

- **现象**：在问号节点进入的随机房（怪物/事件/商店等由掷骰决定）里「重启房间」，房间内容会变成另一批。
- **原因**：问号节点的房间类型是**掷骰**决定的（消耗 RNG）；旧快照捕获于掷骰**之后**，重启并重新进入时会**再掷一次**，用的是已被推进的 RNG → 结果不同。
- **修复**：「重启房间」改用**掷骰之前**的快照回滚 —— 重新进入本节点时重演同一次掷骰与遭遇抽取，用的正是同一份 RNG，**问号房内容与首次完全一致**（牌序同样一致）。

### v0.1.2 · 2026-09-15

**提速：重启不再绕行主菜单**

- 四类重启（房间 / 本层 / 本局 / 新局）与「回到地图」全部改为**直接回滚** —— 省掉「回主菜单 → 再进游戏」的两次场景切换与主菜单资源预载。实测（同角色同房间）黑屏总时长从约 **2.7s → 约 1s**：重启本层 ~0.9s、重启房间 ~1.1s、重启本局 ~1.9s（其中大部分是游戏重建场景的固有耗时）。
- 新增**过场黑幕**：重启期间平滑淡入淡出，不再闪现主菜单画面。
- **稳定性兜底**：直接流程任何一步异常会自动回退到旧流程（日志可见 `直接路径失败…回退主菜单路径`），不会卡死。

**修复**

- **「重新挑战」按钮点不动** —— 按钮的 `ProcessMode` 被误设为 `Disabled`（收不到任何输入），已改为 `Always`。
- **「重启本层」可能回到上一局** —— 用游戏自带流程开新局（如上局死于第 1 幕）时，本层快照会残留旧局数据并覆盖新局；现已按**种子校验快照归属**，不属于当前局的一律走安全回退。
- **重启进行中重复触发** —— 新增重入保护：一次重启未结束时再按快捷键会被忽略并记日志，不再出现两条流程交错导致的黑屏。
- **刀下留人弹窗创建失败会永久冻结战斗** —— 失败时现会自动解除暂停、放行战斗（再次死亡会重新拦截）。

**新增配置**

- `FastRestartSkipMenu`（默认 `true`）：重启时跳过主菜单中转、显著缩短黑屏；如遇异常可改为 `false` 回退旧流程。

**兼容性**

- 兼容 STS2-RitsuLib **0.6.x**（框架大改版）与 0.5.x：升级 0.6.0 请安装官方完整包（含 `shared/`、`compat/`、`assets.zip`，不能只复制根 DLL）。

### v0.1.1 · 2026-09-15

**修复：重启房间后商店物品会"刷新"**

- **现象**：在商店里按 `R` 重启房间后，货架上的卡牌 / 遗物 / 药水会变成另一批（与首次进店不一致）。
- **原因**：重启时房间被**进入了两次**。官方读档流程本身就会依据存档中的地图坐标，自动把你送回本房间 —— 这一次用的随机数与首次进房完全相同（正确的结果）；而 mod 随后又手动进了一次房，商店被**第二次生成**，此时生成用的随机数已被第一次消耗，于是货架"凭空刷新"。
- **修复**：读档已自动重进本房间时，不再重复进房。
- **效果**：重启后商店库存与首次进店**完全一致**，反复重启仍是同一批货。

**顺带收益（同源问题一并修复）**

战斗房、事件房、宝箱房同样不再"生成两次" —— 重开后的**怪物编成、事件内容、宝箱遗物**与首次进房一致，练习与救场场景下的"精确重现"承诺现在覆盖全部房间类型。

**改进：刀下留人改为「回到地图重新挑战」**

死血弹窗的确认按钮不再原地重开战斗，而是**回到进入本房间之前（选路前）的地图**：

- 血量 / 牌组 / 金币 / 药水全部回退到进房前，连地图上的访问记录一并回退 —— 相当于"这一格还没走过"；
- 可以重新选路（走别的节点），也可以重新进入刚才那个节点再战。

首个发布版本：

- **刀下留人** —— 生命归零时冻结战斗，可选择「重新挑战当前战斗」或「放弃本局」
- **战后重新挑战** —— 战斗结算的选牌界面一键放弃奖励、整场重打

- **无痕保护** —— 重启不记失败、不断连胜、不写历史与成就

## 从源码构建

- 需要 .NET 9 SDK
- 复制 `local.props.example` 为 `local.props`，修改为你的游戏路径
- 构建：

```powershell
dotnet build QuickRestart.csproj -c Release
```

构建产物自动复制到 `$(ModOutputDir)`（默认：游戏目录下 `mods/QuickRestart`）。
